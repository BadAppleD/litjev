HOW IT WORKS / 数据来源

      
不是让模型生成 JSON，而是读取下一个 token 的分数。

      
当前实现使用原模型的语言模型输出头 lm_head，没有训练新的分类头，也没有生成计划、解释或答案 JSON。所有 JSON 键和结构由 Python 组装。

      
    
        
  1. 第一次 forward：共享前缀题干、选项和指令只编码一次，得到前缀缓存。标准答案不进入输入。
    2. 
        
  2. 第二次 forward：独立分支复制前缀的 KV 与循环状态，各行仅输入自己的 Field "题号"\nAnswer: 后缀，一次并行计算。各分支看不到其他分支的后缀和答案。
    3. 
        
  3. 最后一层 → 输出头Qwen 文本解码器最后一个 block 的输出，经最终 RMSNorm（model.language_model.norm），再经线性词表投影 lm_head，得到 output.logits。不是 attention 权重或中间层打分。
    4. 
        
  4. 各行独立读出取每行最后一个真实 token（Answer: 的冒号）的候选 logits，再 softmax 和 argmax。各行互相隔离，但每行目录里仍含全部题干，保持与旧版相同的输入语义。
    5.

响应 JSON：哪些来自模型？
字段来源与含义

          
answers.*.logits直接取自模型。原 LM head 的候选词表 logits；转成 float32 后序列化。数组顺序见 provenance.candidate_labels。

          
probabilitiesPython 计算：对候选 logits / T 做 softmax，不是模型口述的置信度，也不是完整词表概率。

          
valuePython 计算：argmax 后映射回输入选项；boolean 映射为 JSON 布尔值。

          
gammaPython 计算：选中项的概率。未校准时不能视为可靠正确率。

          
provenance程序记录的取值位置：层数、槽位索引、绝对位置、词表 ID 和温度；不是模型生成。

          
field_type / model / usage来自输入 schema、加载配置与程序计数；output_tokens 为 0，当前路径 forward_calls 为 2。

          
calibration_fitted / timing来自校准配置与服务端时钟，不是模型输出。准备时间含模型加载/等待；决策时间含编码、排队和推理。
