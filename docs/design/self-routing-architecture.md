# 自路由的 System One / Two：冻结骨干，只训一个决策头

讨论稿，2026-09-18。已定方向：

- 骨干（Qwen3.x）**全部冻结**，权重一个不动。
- 慢路径就是骨干**原生的 thinking 模式**，不改变骨干任何行为。
- 训练只训一个并列在读头旁边的**决策头**。

目标：一次 prefill + 一次 forward，模型自己决定每道题走快答（Jev 读头）还是慢想；
快路径成本不增加一个 token，慢路径只在头说要的时候追加，最终答案永远由读头给出。

## 1. 决策头读什么

读头位置是每条分支 `Answer:` 冒号处。骨干冻结意味着这个位置的表征就是全部信息来源，
头的输入应该把它用足：

| 输入 | 维度（27B） | 来源 | 为什么 |
|---|---|---|---|
| 最后一层 norm 后的 h | 5120 | 第二次前向，hook 在 `model.norm` | 答案分布的直接来源 |
| 一到两层中间层的 h | 5120 × 层数 | `output_hidden_states` | "知不知道自己不知道"的信号常在中层更强 |
| 候选分布统计量 | 约 6 | 已有的候选 logits | max prob、熵、top-2 margin、concentration、候选数、题型 |

中间层选哪几层，用探针实验定：在验证集上逐层训 logistic probe，取 AUROC 最高的一两层。
27B 有 64 层，经验上第 40 到 52 层附近。这个实验本身很便宜，特征一次抽完可以反复用。

结构：拼接后过一个两层 MLP（隐藏 1024，GELU，dropout 0.1），参数量几百万到一千万，
相对 27B 可以忽略，单卡几分钟训完。

## 2. 头输出什么：预测"慢想值不值"，而不是"快答对不对"

只预测"快答案对不对"是不够的：快答错了、慢想也错，升级就是白花钱。
骨干冻结之后慢路径的行为是确定的，所以可以直接学它：

头输出四类联合分布 P(快对, 慢对)：

| 类 | 快 | 慢 | 含义 |
|---|---|---|---|
| 0 | 对 | 对 | 不用想 |
| 1 | 对 | 错 | 千万别想 |
| 2 | 错 | 对 | **该想** |
| 3 | 错 | 错 | 想也没用 |

推理时的路由规则：

```
gain = P(2) − P(1)          # 升级带来的正确率净增益
escalate = gain > λ          # λ 是每次升级的成本，运行时参数
```

好处：训练是纯监督的，**λ 不进训练**。产品上要调升级率，改一个数字，不重训。
同时 `confidence` 字段有了正经定义：P(0) + P(1) = P(快答案正确)，这是校准过的置信度，
直接替换现在的 `concentration()`。

`score` 和 `noul` 题型的"对错"用阈值定义：score 看加权下标与真值的距离，noul 看 P(yes) 是否跨过 0.5。
这两类题型的标注数据比 choice 少，头里带题型 one-hot 让它可以分别学。

## 3. 训练数据怎么来

因为慢路径是冻结骨干的原生 thinking，标签完全可以**自动产生**，不需要人标"该不该想"：

1. 对每条样本跑一次 S1，记录读头位置的特征和快答案。
2. 对同一条样本开 thinking 跑一次 S2，读 `</think>` 之后的头，记录慢答案。
3. 与金标比对，得到四类标签。

需要金标的只是"答案对不对"。数据来源：

- **choice**：MMLU-Pro 验证集、ARC、GPQA、BBH 的选择题子集，覆盖不同难度和领域，避免头只学到 MMLU 的风格；
- **score / noul**：现成数据少，用有标注的分类数据改写（情感等级、是否安全、是否需要转人工），
  加上从 choice 数据派生的 noul（"答案是 X 吗"）；
- **视觉**：Doom / chess 没金标，先不进训练集，只做迁移测试。

规模：几千到几万条样本足够训一个探针级别的头。S2 生成是主要成本，27B 每条几秒到十几秒，
几万条要多卡跑一天量级；先在 Qwen3 4B 上把管线跑通。

**永远不用测试集标签。** 训练/验证/测试按数据集划分，不按题随机分，才能看出跨领域泛化。

## 4. 慢路径接法

被头标记的分支，从**自己的缓存**继续：切换到允许推理的 system 提示不可行（前缀已经算完），
所以慢路径的做法是在这条分支后追加 `<think>` 起始 token 直接 generate，
停在 `</think>` 或预算，再接一个 `Answer:` 边界，重新读头。

骨干没变，所以这段推理就是 Qwen 自己会写的推理。多条被升级的分支批在一起生成。
`usage.output_tokens` 等于思考 token 总数。

一个要验证的点：现在的快路径 system prompt 写着"不要推理"，`<think>` 硬插进去骨干会不会拒绝写。
如果会，方案是把 system prompt 改成中性的（不禁止推理，但快路径通过 `enable_thinking=False`
的模板关掉），这是前缀文本的改动，不是骨干的改动。

## 5. 头的生命周期

头是一个小的 safetensors 文件，元数据绑定：

- 骨干 `model_id` + `revision`
- `SLOT_FORMAT`（后缀格式）
- 抽特征的层号列表
- 训练数据清单和日期

任何一项变了头就失效，和现在 `calibration.json` 的失效规则一致。
加载：`litjev --model Qwen/Qwen3.8-27B --decision-head head.safetensors`。没有头时行为和现在完全一样。

## 6. 在 LitJev 里的落点

改动集中，骨干加载路径不动：

- `backend.py::_score`：第二次前向加 `output_hidden_states=True`（或在选定层挂 hook），
  取读头位置的向量，随 `RawFieldScores` 一起返回。被升级的分支批量 generate 后二次读头。
- 新模块 `heads.py`：`DecisionHead` 定义、加载、保存、元数据校验。
- 新模块 `routing.py`：四类概率到 escalate 决策，λ 是参数。
- `decision.py`：`confidence` 改为头给的 P(快对)，`concentration` 保留在 debug 里对照；
  每题 provenance 加 `system: "one" | "two"` 和四类概率。
- 新命令 `litjev-collect`：跑 S1 + S2，导出特征和标签；`litjev-train-head`：训头。
- `/v1/systemone` 不动。自路由走 `/v1/systemtwo`，请求体多一个可选 `routing: {"lambda": 0.1, "budget": 512}`。

## 7. 评测

MMLU-Pro 测试集加至少一个训练没见过的数据集，三条基线一条主线：

| 线 | 看什么 |
|---|---|
| S1 | 准确率、延迟 |
| S2 全开 | 准确率上限、延迟代价 |
| S1 + concentration 阈值 | 无训练门控的 coverage–accuracy 曲线 |
| S1 + 决策头，扫 λ | 同上曲线，应该整体在上方 |

两个核心指标：

- 头预测"快答对不对"的 AUROC，对比 concentration 的 AUROC。这是"模型知不知道自己不知道"。
- 在 20% 升级率下拿到 S2 全开增益的比例。

如果冻结骨干的头就能拿到明显更高的 AUROC，说明路由能力本来就在表征里，这条路成立。
如果拿不到，问题在特征层选择或数据覆盖，而不是要动骨干。

## 8. 明确不做

- 不训骨干，不做 RL，不做蒸馏。慢路径的推理质量就是骨干原生水平。
- 不让头看题目文本或 state 文本，只看隐状态和分布统计。头不是第二个模型。
- 不改 `/v1/systemone`。

## 9. 第一步

在 Qwen3 4B 上把管线跑通：抽特征、逐层探针、训头、画一条 coverage–accuracy 曲线。
这一步不需要 H100，也不需要动 27B。曲线出来再决定要不要上 27B。

### 实现状态（2026-09-18）

管线已经落地，用法见 [`../system-two.md`](../system-two.md)：

- `backend.py`：快路径可选返回读头位置的多层隐状态；`think()` 慢路径对被升级的题重跑
  `<think>…</think>` 再读同一个 `Answer:` 边界。骨干不变。
- `heads.py`：`DecisionHead`（MLP，四类输出）、特征构造、训练、AUROC、coverage 曲线。
- `routing.py`：`gain = P(2) − P(1) > λ` 的升级规则。
- `decision.py`：有头时 `confidence = P(快对)`；升级题的答案由慢路径读头给出。
- `collect.py` / `training.py` + `litjev-collect` / `litjev-train-head`：自动标签、按类别划分、逐层探针。
- `api.py`：`/v1/systemtwo`，请求体多一个可选 `routing`；`/v1/systemone` 不变。
- `scripts/collect.sbatch`：Slurm 分片采集。

小模型上的等价性测试覆盖：读头隐状态与全量前向一致、慢路径 logits 与手工拼接序列的全量前向一致。

### 集群上的第一轮结果（Qwen3.5-4B，2026-09-21）

两个待验证点都有了答案：

- `<think>` 硬插进快路径前缀，骨干一个 token 就关掉，因为 `enable_thinking=False` 的模板已经带了空 think 块。
  慢路径改为用开启 thinking 的模板单独构造提示（题目放 user 轮），骨干正常写推理。
- 512 预算在 MMLU-Pro 上不够，98.5% 的题打满预算；下一轮用 1024。

1000 题、14 个学科、留出 3 个学科测试：快答 0.578，慢答 0.616；只用分布统计量的头在 λ=0 时升级 47%，
准确率 0.642；layer 16 隐状态过 64 维白化 PCA 的头在 λ=−0.05 时升级 55%，准确率 0.642。
两种路由都超过"全部慢想"。原始 2560 维隐状态在这个数据量下过拟合，比统计量基线还差；
单次验证集选层会选错，改成按学科 K 折后选出的候选和测试集一致。详见 `../system-two.md`。
